# /test - Comprehensive Testing, Mocking & Fixture Engine

$ARGUMENTS

---

## 🎯 Purpose & Core Principles

Activates **UNIFIED TESTING & QUALITY MODE** to discover test coverage gaps, generate automated test cases, simulate backend APIs via MSW mocks, and generate relational test data.

> **IRON INVARIANTS:**
> 1. **BEHAVIOR OVER RAW LINE COVERAGE:** Prioritize edge cases, validation boundaries, and state mutations over superficial line coverage.
> 2. **CONTRACT FIDELITY:** Mock handlers and test fixtures must strictly match actual TypeScript types, Zod schemas, or DB models.
> 3. **RELATIONAL INTEGRITY:** Seed data must maintain foreign-key consistency and idempotent execution (`upsert` or clean-before-insert).
> 4. **ZERO PRODUCTION CONTAMINATION:** Mock handlers and seed generators must be isolated from production build bundles.

---

## ⚙️ Argument Parsing & Usage Modes

```text
# 1. Test Coverage Audit (Discover gaps across FE & BE):
/test [--fe|--be|--full] [--changed] [--write-tests] [--run]

# 2. Mock API & Network Simulation:
/test --mock <endpoint or feature> (e.g. /test --mock POST /api/checkout)

# 3. Relational Test Data & Seeding:
/test --seed <model or domain> [--count <N>] [--locale <vi|en>]
```

### Flags:
- `--write-tests`: Generates real automated test files (Vitest, Jest, Playwright) for identified coverage gaps.
- `--mock`: Creates contract-faithful MSW (Mock Service Worker) handlers or fixture responses.
- `--seed`: Generates relational DB seed scripts or JSON fixtures with foreign-key integrity.
- `--run`: Executes the relevant test runner and reports pass/fail counts.
- `--changed`: Restricts testing/audit scope to git-modified files and their regression blast radius.

## 🧪 Mode B: API Mocking & Network Simulation (`--mock`)

Generates MSW (Mock Service Worker) handlers or isolated HTTP test servers:

```typescript
// Standard MSW Handler Structure generated by /test --mock:
import { http, HttpResponse, delay } from 'msw';

export const handlers = [
  http.post('/api/v1/orders', async ({ request }) => {
    await delay(300); // Realistic latency
    const body = await request.json();

    // Error simulation condition:
    if (!body.items?.length) {
      return HttpResponse.json({ error: 'Cart is empty' }, { status: 400 });
    }

    return HttpResponse.json({
      id: 'ord_mock_123',
      status: 'confirmed',
      totalAmount: 450000,
    }, { status: 201 });
  }),
];
```

## 🎲 Mode C: Relational Synthetic Seed Data (`--seed`)

Generates typed, relational fixtures or idempotent DB seeders (Prisma, Drizzle, TypeORM, raw SQL):

- **Foreign-Key Graphs:** Ensures parent entities (Users, Tenancies) are created before child entities (Orders, Invoices).
- **Realistic Fixtures:** Uses localized names, valid email formats, realistic phone numbers, and coherent financial amounts.
- **Idempotency:** Implements `upsert` or unique deterministic seeds to ensure scripts can run repeatedly without primary key collisions.
